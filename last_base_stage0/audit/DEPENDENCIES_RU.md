# Зависимости исходной версии 0.20.0

Это карта существующих связей. Она не задаёт новое устройство игры и не является выполнением Stage 1.

## Порядок запуска, который нужно сохранить

1. HTML создаёт Canvas, HUD, джойстики и основные окна. Telegram SDK подключается внешним скриптом.
2. Основной inline JS определяет помощники, звук, мир, игрока, предметы, ввод, update/draw и исходное сохранение.
3. Последовательные блоки версий добавляют данные, DOM, стили, обработчики и обёртки существующих функций. Часть обёрток вызывает сохранённую предыдущую реализацию.
4. После установки расширений вызываются `loadGameProgress()` и установка `gameSaveReady`. Затем выдача стартовых предметов, HUD и обработчики автосохранения.
5. `resizeCanvas()`, `applyControls()`, `updateCamera()` и `gameLoop()`. Telegram fullscreen вызывается позднее таймером; меню фермы связывается в конце скрипта.

Объявления функций, глобальные `let/const`, чтение `window.V...` и немедленные побочные действия имеют разные правила доступности. Механический переход на `type="module"`, strict mode или асинхронную загрузку изменит эти правила. В Stage 0 ничего из этого не выполнялось.

## Основные владельцы и связи

| Область | Фактическое размещение | Существенные связи |
|---|---|---|
| Игрок и ввод | `player`, `scene`, `handSlots`, `V014Controls`, `V0105` | Коллизии, маршруты, прицел, инвентарь, UI, высота на стене |
| Инвентарь | `bag`, `equipment`, `storageChests`, `V010Inventory`, `V013Inventory` | Быстрые слоты физически хранят экземпляры; переносы сохраняют UID, патроны и данные рыбы |
| Оружие | `V09Craft.weapons`, `V010Combat`, `V0162Magazines` | Таблица оружия находится в крафте; реальная ёмкость зависит от установленного магазина; состояние перезарядки привязано к UID |
| Предметы и рецепты | `ITEM`, `V092_ICONS`, `V09Craft.recipes` | Другие модули расширяют определения после их создания; это не окончательные таблицы в месте первого объявления |
| Улучшения | `V0161Upgrade`, `V010Combat`, `V014Robots`, `V018Build` | Стоимость, ограничения и вычисление характеристик распределены между системами |

| База | `V020Walls`, `V091Fortress`, `V015Base`, `V018Build` | Секции влияют одновременно на коллизии, подъём, свет, маршруты, турели и saves |
| Дрон | `V014Robots`, `V0141DroneMotion`, `V0141DroneUI`, `V0151Station` | Один объект состояния; токен в инвентаре; двери и энергосистема; уровни мира; аварийный подбор |
| Турели | `V016Turret` | Стена-опора, отдельный предмет, боезапас, улучшения, враги и сохранения |

| Ферма | `farmCrops`, `farmState`, `V011Farm`, `V0141Farm` | Индекс культуры в save, посадочный предмет, 50 растений на грядке, индивидуальные времена и полив |

| Рендер и свет | Общий `ctx`, `V011Art`, `V0141Trees`, `V016Lighting` | Порядок слоёв/Y-сортировка, атласы, геометрические кэши, источники света |
| Окна | Основные overlay + `V0161UI` и локальные UI модулей | Поглощение закрывающего жеста, скрытие HUD, состояния добычи/маршрута, CSS-переопределения |

| Сохранения | Основные функции + `V09Saves`, `V010.modules` и поздние обёртки | Пять слотов, резервные копии, модульные schema, миграции до/после валидаторов |

## Важные ограничения для следующего этапа

- Нельзя считать более раннюю функцию неиспользуемой только потому, что позднее она переопределяется: прежняя реализация может храниться в замыкании.
- Порядок вставки CSS и регистрации обработчиков — часть текущего поведения. Перестановка одинаково специфичных правил меняет UI.
- Общий `player` и `scene` участвуют в чужих системах; их преобразование в коллекцию игроков не относится к безопасному разрезанию файлов.
- `Date.now()`, `performance.now()` и `frameScale` используются для разных часов. Не заменять их одним временем одновременно с извлечением модулей.
- Часть нормализации предметов и характеристик происходит при render/capture. Сначала сохранить это поведение и его тесты; отделение побочных действий — следующий самостоятельный шаг.
- `source/build.py` собирает HTML через замены в `baseline_0.19.1.html`. После будущего разделения должен остаться один источник истины; сейчас скрипт сборки не запускался и не менялся.
- `dependencies.json` содержит порядок обнаруженных IIFE, экспорты и места установки обёрток. Это консервативная текстовая карта, не доказательство всех динамических связей.
- Модель DOM текущих тестов неполная: при будущем вынесении скриптов загрузчик тестов тоже должен научиться читать внешние файлы в реальном порядке. Игровой runtime ради тестов менять не нужно.
