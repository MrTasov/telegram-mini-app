# LAST BASE 0.29.0 — Audio Unlock Hotfix 1

Исправление поверх `Visual / Animation / Audio Polish 1`. Оно касается запуска и восстановления трёх уже добавленных эффектов: шагов, ударов по дереву и ударов по породе. HUD patch не начат.

## Причина

В прежнем коде `unlockGameAudio` слушал только первые `pointerdown` / `touchstart`, в фазе всплытия. У касания разрешающий воспроизведение жест может наступать при отпускании пальца; некоторые игровые кнопки останавливают всплытие. После неудачного первого `resume()` обработчики удалялись. Состояние `interrupted` после сворачивания также не восстанавливалось.

Кроме того, флаг `audioLoadStarted` навсегда запрещал повторную загрузку даже после ошибки запроса или декодирования WAV. Прежние проверки синхронизации начинали с уже работающего AudioContext и загружали буферы напрямую, поэтому не выявляли ошибки запуска через UI.

Основание для проверки браузерного поведения: [MDN — user activation](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/User_activation) и [MDN — AudioContext state](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/state). Это найденные в коде воспроизводимые причины тишины; конкретное состояние браузера на устройстве пользователя удалённо не наблюдалось.

## Исправление

- Обработчики `pointerdown`, `pointerup`, `touchend`, `click`, `keydown` работают в capture-фазе. Остановка всплытия кнопкой или джойстиком не мешает аудио.
- Обработчики остаются доступными после первого жеста. `resume()` вызывается синхронно внутри пользовательского события для `suspended` и `interrupted`.
- Работающий контекст повторно не запускается; новый AudioContext на каждый жест не создаётся.
- Успешно декодированные WAV повторно не запрашиваются. Параллельные запросы одного файла объединяются. Неудачная загрузка может повториться при следующем взаимодействии, не чаще раза в секунду на файл.
- Автоматических таймеров повторного воспроизведения нет. Синхронизация с шагом/ударом сохранена. Сохранённая громкость 0 остаётся 0.

Из игровых исходников изменён только `src/core/runtime.js`. Собраны `js/game.js`, source map и build-info; обновлены cache tag в `index.html`, аудит исходников, README и QA. Все assets, включая три WAV, совпадают с предыдущей сборкой побайтно. Gameplay, saves, corpse cache и масштаб ×1,2 не менялись.

Cache tag: `0.29.0-audio-unlock-hotfix-1`. Версия игры 0.29.0, формат сохранений 3.

Проверены касание/отпускание, кнопка с `stopPropagation`, клавиатура, click, отказ первого resume, прерывание/сворачивание, ошибка сети, ошибка декодирования, повторные жесты без дублирования загрузок, сохранённый mute. Результаты: `qa/results/audio-unlock-before.json`, `audio-unlock.json`, `audio-hotfix-summary.json`. Запуск нового теста: `node --expose-gc qa/audio-unlock.cjs . qa/results/audio-unlock.json`. Он также добавлен в общий `npm test`.

## Установка и ручная проверка

1. Загрузите распакованное содержимое ZIP на GitHub с сохранением папок. Особенно важно обновить одновременно `index.html` и `js/game.js`.
2. Полностью закройте и снова откройте игру. Выберите Continue / Продолжить обычным нажатием.
3. Убедитесь, что громкость в игровых настройках выше 0 и медиагромкость устройства включена.
4. Проверьте шаги, удары по дереву и камню; сверните игру, вернитесь и снова коснитесь управления.

В сборке по-прежнему присутствуют три WAV из Polish 1. Шесть исторических необязательных MP3, включая gunshot, ранее отсутствовали; этот hotfix не создаёт новые звуки выстрелов, животных и зомби.

Архив проверяется по CRC и полной распаковкой с SHA-256 каждого файла. Следующий патч не начат.
