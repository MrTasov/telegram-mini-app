# LAST BASE 0.27.0 — Multiplayer Readiness Report

Этап 7 завершает подготовку single-player архитектуры. В сборке по-прежнему **один реальный игрок, один игровой цикл и пять локальных слотов**. Подключение второго клиента пока невозможно. Сервер, transport, WebSocket, лобби, аккаунты, replication, prediction и rollback не добавлены.

## READY NOW

| Область | Фактическая подготовка в коде |
|---|---|
| Player identity | `src/state/identity.js` хранит внутренний `playerId`; `src/state/actors.js` предоставляет `GameActors.localId`, `get(id)` и живое представление существующего игрока. ID не зависит от имени сохранения. Загрузка заменяет содержимое контейнеров, но представления не удерживают старые `bag`/`equipment`. |
| Input → commands | `src/input/actions.js` оставляет локальные проверки окон и открытие UI. MOVE, AIM, FIRE, INTERACT, RELOAD, SELECT_SLOT, SNEAK передаются в `GameSimulation.execute({actorId,type,payload})` из `src/simulation/commands.js`. PC и Touch используют тот же исполнитель. Чужой ID отклоняется до обработки даже команды отпускания Fire. |
| Enemy identity | `makeZombie()` в `src/core/input-combat.js` выдаёт монотонный `instanceId`. Тип берётся из существующего `type`, через `typeId`; дополнительных X-типов нет. ID сохраняется при загрузке и перестановке массива. Новый враг, занявший освободившуюся ячейку, получает новый ID. Старые AI `worldId`/runtime serial оставлены для сохранения поведения и случайных последовательностей. |
| Drone target | В `src/drones/companion.js` цель — `state.targetId`; разрешается через `GameIdentity.enemy(id)`. Удаление или замена элемента массива больше не перенаправляет атаку на другого врага. `targetIndex` остался только вычисляемым представлением совместимости для старого формата и расширений. |
| Map / kill events | Маркеры врагов в `src/ui/context-map.js` и `combatkill` в `src/combat/weapons-crafting.js` используют `instanceId`. Индекс массива больше не выдаётся за постоянную идентичность. |
| UI and stats | `equipmentSnapshot()` и `itemView()` читают значения без изменения предметов/игрока. Из `renderEquipment`, карточки предмета, выбора магазина и Ammo HUD удалены записи gameplay state. `refreshStats()` выполняет commit при изменении экипировки и restore; `syncAmmo()` обновляет старое поле совместимости при игровых изменениях/tick. Открытие карточки не создаёт UID и не ограничивает HP. |
| World time / events | `src/world/clock.js` и `src/world/events.js` работают без DOM, player, camera и wall clock. Один снимок модификаторов относится ко всему миру. День X вычисляется из календаря; повторные START/load не умножают усиление повторно. |
| World versus client scene | Из `GameState.world` убрана ссылка на текущую сцену локального клиента. Она доступна через actor и `GameState.render`; world содержит clock/events/identity. Это уточняет границу владения, сохраняя текущий single-player переход между зонами. |
| Save migration | `saveVersion: 2`, миграция `1 → 2` добавляет `identity027`. Она завершается после исторических миграций, которые могут расширить массив врагов. Валидация проверяет уникальность ID, счётчик и ссылку цели до изменения мира. Старые adapters идут в прежнем порядке; существующие ключи и пять слотов сохранены. |

### Identity audit

ID имеют область одного сохранённого мира. Совпадение `player:1` в двух независимых слотах допустимо: это не аккаунт и не глобальный пользовательский ID.

| Сущность | Type ID | Instance ID / фактическое ограничение |
|---|---|---|
| Игрок | `player` | `player:N`, сохраняется в `identity027.playerId`; сейчас один actor. |
| Враг | `normal`, `fast`, `heavy`, `leaper`, `bloater` | `enemy:N`, счётчик сохраняется; порядковый номер в массиве не используется как ID. |
| Дрон | `drone014` | Существующий `INSTANCE_ID`/`robotId`. Написание совпадает с type по исторической причине, но эти роли разделены в коде. Дрон пока singleton. |
| Турель | Ключ `ITEM`, `typeOf()` | `turretData.id` / ID установленной турели. `src/base/turrets.js` сохраняет `nextId`, проверяет дубли и сохраняет ID при pack/deploy. |
| Оружие, экипировка | Ключи `ITEM` и `V09Craft.weapons` | Существующий `gear-N`/`uid` сохранён. Переносы предмета сохраняют UID. Нормализация остаётся в `ensure`, mutation/restore/capture; это ещё не единый transaction service создания всех предметов. |
| Магазины, патроны, материалы | Стабильные ключи типов | Текущая механика использует стопки `type + qty`, а оружие — `magazineType + rounds`. Отдельного физического экземпляра магазина с ID нет. Такая модель сознательно сохранена. |
| Стены, ворота, двери, разрушаемые конструкции | Существующие kind/definition | ID секций и записей `V018Build.structures`, существующие сохранения HP/уровня по ID. |
| Деревья, руда, камень, loot-контейнеры | Существующие type/kind | Постоянные ID карты (`tree…`, ore ID, `stone018_…`, ID здания/машины). Это ID контента, привязанные к сохранённой карте; переименование требует миграции. |
| Хранилища / crafting stations | Существующие kind/type | Interaction ID остаются стабильными при текущей фиксированной карте. Для части inventory API номер хранилища — адрес контейнера, а не универсальный entity ID. |
| Dropped items / projectiles | Зависит от текущей подсистемы | Полноценного общего drop-entity owner нет; `V014LooseLoot` — необязательный hook сбора. Пули — временные объекты без постоянного сетевого ID. Новая механика выбрасывания предметов не добавлялась. |

## NEEDS NETWORKING STAGE

1. **Разделить состояние акторов.** Новый ID и command envelope дают точку входа, но `GameActors` сейчас представляет только локального игрока. Прежде чем принимать команды других игроков, необходимы отдельные actor-owned movement/aim, health, inventory, equipment, reload/practice, projectile ownership и interaction/work state. Нынешний исполнитель намеренно отклоняет неизвестный actor.
2. **Определить авторитет и жизненный цикл сессии.** Выбрать модель сервера/хоста, владение сущностями, tick/time, подключение/отключение и восстановление actor state. Сейчас этого кода нет.
3. **Расширить команды для транзакций.** Inventory transfers, crafting, upgrade, drone/turret UI пока вызывают существующие локальные API. Для сети потребуются адреса actor/container/entity, проверки расстояния/владения/ресурсов, атомарное выполнение и защита от повторной команды. UI-индекс ячейки может оставаться адресом, но предмет нужно проверять по ожидаемой идентичности/ревизии.
4. **Общий combat и AI.** Целями AI должны стать допустимые акторы. Потребуются правила повреждений, friendly fire, attribution выстрелов/убийств, смерть/возрождение и принадлежность дронов/турелей. Ни одно из этих gameplay-правил сейчас не вводилось.
5. **Сетевой обмен.** Только на этом этапе добавлять протокол, авторитетную проверку команд, snapshots/deltas, порядок доставки, spawn/despawn, resync и reconnect. Prediction/интерполяция выбираются по фактическим требованиям; текущий код не является готовым сетевым протоколом.
6. **Предметы и ресурсы.** Решить, какие стопки/магазины требуют instance identity в сетевых транзакциях, добавить revisions/ownership без изменения принятой механики. Проверку уникальности всех предметов и создание UID следует довести до общей границы inventory transactions.
7. **Общие события.** Один авторитетный WorldClock должен вызывать WorldEvents; клиентам передавать состояние, а не самостоятельно запускать календарь. Текущий модуль уже вычисляет modifiers независимо от локального UI, но репликации нет.
8. **Отдельное решение о multiplayer persistence.** Single-player slots не заменены серверными/cloud saves. Формат общего мира и подключённых акторов, права загрузки и восстановление сессии нужно проектировать отдельно.

## KNOWN LIMITATIONS

`GameSimulation` пока вызывает существующие API. Например, INTERACT может открыть локальное окно, а reload проверяет `menuOpen`. Новый command boundary не превращает всю старую игру в headless simulation. Перед приёмом удалённых команд такие операции нужно разделить на изменение состояния и результат для UI нужного клиента.

| Система | Оставшееся ограничение и место в коде |
|---|---|
| Player / movement | `src/core/world-inventory.js` содержит один `player`; `core/input-combat.js` — `moveX`, `movePower`, aim и navigation для него. Actor view не создаёт независимые наборы этих переменных. |
| Combat / weapons | `combat/weapons-crafting.js` хранит один reload, burst, practice и текущий hand slot. `shoot`, `damagePlayer`, часть правил проверки доступности ещё используют single-player context. Сетевой executor пока нельзя безопасно подключить к этим API для второго игрока. |
| Enemies | `combat/monsters.js` выбирает и атакует глобального игрока. Spawn/retirement использует расстояние до него и `visibleOnScreen`; это нужно заменить областью интереса всех игроков. Текущая политика сохранена ради баланса и FPS. |
| Drones | Цель атаки исправлена, но `companion.js` хранит один companion, следует за локальным `player`, проверяет глобальный `scene`; несколько владельцев/дронов требуют отдельного runtime на экземпляр. |
| Turrets | Постоянные ID и данные экземпляров уже есть. Однако `base/turrets.js:tick` приостанавливается из-за локальных `scene`, `menuOpen`, `playerDead`, `document.hidden`. В сети жизнь мира не должна зависеть от окна одного клиента. |
| Inventory | `registry-slots.js` и `physical-slots.js` адресуют общий bag/equipment/quick. Нет разграничения доступа нескольких акторов к одному сундуку и одновременных транзакций. Отдельные устаревшие inventory/render entry points всё ещё объединяют уведомление об изменении и перерисовку. |
| Crafting / upgrades | Очередь и ресурсы уже имеют владельцев состояния, но операции используют локальные inventory/location checks. Нужно определить общую станцию, actor requests и доступ нескольких игроков. Рецепты и цены не менялись. |
| Destructibles / placed objects | Постоянные ID и HP существуют. Ремонт/улучшение и проверка занятости ещё ориентированы на одного игрока и одного дрона; нужны конкурентные команды и список occupants. |
| World transitions | Глобальный `scene` по-прежнему управляет surface/bunker, collision wrappers и обновлением подсистем. Сцена больше не выставляется как свойство authoritative world owner, но полноценной одновременной simulation разных зон нет. Это существенная отдельная работа. |
| Camera / map / UI | Камера, zoom, открытые окна и selection локальные. Некоторые старые AI/spawn проверки всё ещё читают visibility камеры. Их нельзя просто перенести на сервер без изменения зависимости. |
| Time / Day X | Clock/event-модули чистые, однако single-player driver остаётся в `render/lighting.js`, а пауза/смерть/скрытая вкладка влияют на текущий loop. Для общего мира нужен независимый driver и согласованная политика паузы. |
| Saves | `saveVersion 2` — локальная совместимая миграция, не multiplayer snapshot. Исторический capture ещё выполняет нормализацию gear и `turrets.settleUnsupported()`. Для сетевых read-only snapshots это нужно вынести в явный simulation commit. Старые приложения не читают новый формат 2. |

Временная атмосфера/звук Дня X не добавлены. Для будущего события с иной схемой сохраняемых HP-modifiers потребуется дополнить per-owner save metadata; текущая совместимость проверена для существующего Дня X. Модуль событий допускает дополнительные каналы, но renderer/audio/weather consumers ещё не реализованы.

Автоматические результаты и замеры приведены в `STAGES_6_7_REPORT_RU.md` и `qa/results/`. Физический телефон, Telegram и браузерный compositor требуют ручной проверки пользователя. После этой сборки работа остановлена; настоящий multiplayer не начат.
