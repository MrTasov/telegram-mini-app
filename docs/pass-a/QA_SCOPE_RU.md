# Область проверки Pass A

База — только заново распакованный приложенный ZIP Claude. Папки и файлы отменённой попытки не используются.

1. Полный исторический `qa/run.cjs` запускается один раз с ограничением 300 секунд на дочернюю группу. Исходные результаты сохраняются в `qa/results/pass-a-historical` перед адресными повторными проверками. Старые тесты не считаются успешно пройденными, если ожидают прежнюю геометрию, отключённую Farm или побайтовую неизменность мигрируемых save-блоков.
2. `qa/pass-a.cjs` — новая проверка принятого FINAL V2 через реальные runtime owners: два этажа в одной сцене, миграция, вода, грядки, часы, DEV, Power, контакт зомби.
3. `qa/pass-a-chapter.cjs` — существующий реальный Chapter 1 сценарий с актуальными координатами Core и свободной комнаты, без изменения игровых требований.
4. Повторная проверка Siege/Defense/I1, Research, Archive и реестра save owners после локальных изменений. Исходные негативные результаты не удаляются.
5. `qa/pass-a-performance.cjs` — последовательные ограниченные измерения Native Canvas2D, 20 прогревочных и 80 измеряемых кадров, flushTimers, viewport 390×844, запрошенный DPR 3, производственный DPR 2. Две одинаковые сцены измеряются на приложенном runtime и на Pass A; новая Farm L2 — только на Pass A. Это не измерение FPS физического телефона.
6. `qa/pass-a-render.cjs` — изображения обоих этажей через настоящий Canvas2D. DOM моделируется; Chromium/WebKit/Telegram в этой среде не проверены.

После адресных исправлений весь исторический набор повторно не запускается. SHA-256 runtime в каждом отчёте позволяет отличить полный первоначальный прогон от финальных адресных проверок.
