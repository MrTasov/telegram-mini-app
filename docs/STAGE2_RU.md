# Этап 2 — состояние и сохранения

Основа: принятая пользователем версия 0.21.0, вручную проверенная на компьютере и телефоне. Результат: 0.22.0. Этап 3 не начат.

## Владельцы состояния

`GameState` — единый каталог из 15 владельцев. `session` действительно хранит семь служебных значений сохранения: готовность, блокировку записи, отложенный таймер, проверенную копию, активный слот, имя и транзакцию восстановления. Игровые владельцы дают живой доступ к уже существующим объектам и API. Второй параллельной модели мира нет.

| Владелец | Состояние / существующий модуль |
|---|---|
| player | персонаж, уровень мира, смерть |
| inventory | рюкзак, экипировка, хранилища, быстрые слоты, слот усиления |
| combat | оружие и его состояние, пули, существующий Combat API |
| enemies | актуальный массив врагов и Monster API |
| world | деревья, руда, лут, районы, город |
| base | участки стен, двери, укрепления и строительство |
| drones | единственный существующий дрон, его состояние и команды |
| turrets | установленные пулемёты и команды |
| power | генератор, батарея и распределение энергии |
| crafting | производство и очередь |
| farm | актуальные грядки, полив, животные и ручные команды |
| progression | существующий модуль прогрессии |
| render | камера, карта и освещение |
| ui | выбранные объекты и открытые окна |
| session | служебное состояние сохранений |

Геттеры важны: `bag`, `storageChests`, `zombies`, `farmState` заменяются при восстановлении и некоторых операциях. Каталог всегда возвращает текущую ссылку. Функции и внутренние состояния закрытых модулей остаются у этих модулей. Старые игровые глобальные переменные ещё существуют как совместимый слой; это постепенная миграция, а не заявление, что весь проект уже избавлен от globals. Для семи перенесённых save-переменных оставлены диагностические get/set-алиасы без отдельной копии значений.

Контракты `GameState.describe()` указывают исходник-владелец, сохраняемые поля и временные данные. Тест проверяет, что каждый корневой ключ сохранения имеет владельца либо относится к метаданным. DOM, жесты, кэши рендера и маршрутные таймеры не попадают в save автоматически.

## Явная цепочка сохранения

`src/save/pipeline.js` управляет тремя операциями: capture, decode, restore. 17 обработчиков capture, 19 decode и 20 restore зарегистрированы по стабильным именам. Последний зарегистрированный адаптер остаётся внешним — сохранён прежний порядок входа, вызова предшественника, выхода и `finally`.

В игровых файлах больше нет присваиваний `captureGameProgress = ...`, `decodeGameProgress = ...`, `restoreGameProgress = ...`. Совместимые функции входа делегируют в `GameSave`. Реестр закрывается перед первым load; дубликаты, поздняя регистрация и неверный порядок вызывают явную ошибку запуска.

Семь существующих подсистем V010 используют тот же единый реестр. Их порядок capture/validate/restore остаётся: world → inventory → craft → combat → energy → progression → camera. Существующий `V010.modules` — ссылка на этот реестр, а не его копия.

Проверка `qa/adapter-preservation.json` подтверждает неизменность тел всех 56 адаптеров и трёх корневых функций после учёта замены доступа к состоянию и метаданных версии. Точный diff — `docs/stage2-source.patch`.

## Формат и совместимость

Сохранены старые ключи localStorage, пять слотов и их независимые резервные копии. Сохраняются корневой `schema: 2`, имена полей `v09`, `v010`, `robots014`, `base015` и остальные существующие схемы подсистем. Переименование этого payload сейчас создало бы дополнительный риск без пользы игроку.

Добавлено одно поле: `saveVersion: 1`. Номер формата отделён от номера релиза. Старые saves без него считаются форматом 0; миграция 0 → 1 добавляет только версию конверта. Старые игровые миграции, включая 0.19.1 → новый периметр, исполняются в исходном порядке. Существующий допуск версий игры дополнен 0.22.0. Неизвестный будущий формат отклоняется до применения состояния.

Восстановление проверяет отдельную JSON-копию входа до запуска restore-адаптеров. Если передан тот же объект, который уже прошёл decode, его сериализованное содержимое сравнивается с проверенной копией: неизменённый объект не проверяется второй раз, любое изменение запускает проверку заново. Записи используют WeakMap и не удерживают освобождённые объекты. На всё время применения блокируется планирование автосохранения; флаг снимается через `finally`. Неверный импорт не начинает загрузку и не выделяет слот. Исходный объект данных не становится живым рюкзаком/дроном через общую ссылку.

Существующие IDs ресурсов, предметов, оружия, рыб, дрона, турелей, стен и мира сохраняются. Зависимости, которые пока используют индексы массива (в том числе некоторые связи врагов и грядок), не переводились на новые IDs в этом этапе. Порядок массивов и связи между ними сохранены и проверены. Это остаётся отдельной задачей будущих этапов, прежде чем утверждать готовность к сетевой синхронизации.

## Отдельно исправленная старая ошибка

В 0.21.0 «Новая игра» могла завершаться сообщением об ошибке хранилища. Проверка выявила фактическую причину: шаблон новой игры создавался до регистрации всех электрических устройств. Его собственная валидация затем сообщала «Неполное сохранение электрических контуров». Ошибка воспроизведена на неизменённой принятой версии.

Теперь полный шаблон создаётся один раз, после инициализации всех модулей и до загрузки любого слота. Каждая новая игра получает отдельную копию. Состояние ранее загруженной игры — повреждения стен, груз и улучшения дрона, День X, грядки — не наследуется. Старый ранний шаблон оставлен исключительно для исторических миграций. Стартовый баланс не менялся.

## Порядок загрузки и дальнейшего редактирования

1. Создаются каталог владельцев, правила формата и save-реестр.
2. В прежнем порядке инициализируются игровые исходники; регистрируются адаптеры.
3. `save/finalize.js` проверяет порядок и полноту реестра, фиксирует начальный шаблон, закрывает регистрацию.
4. Только после этого `bootstrap.js` загружает слот и запускает игровой цикл.

При изменении порядка сохранений нужно осознанно обновить контракт `save/finalize.js` и соответствующие проверки. Новый save-формат требует миграции в `save/format.js`. Нельзя молча менять старые IDs или выводить их из отображаемых названий. Сборка остаётся прежним объединением classic scripts; это сохраняет область видимости и порядок исполнения.

Полное устранение игровых глобальных переменных, переработка tick/draw, новые content definitions и миграция assets в Этап 2 не входят. Следующий этап — по отдельной команде после ручной проверки.

## Ручная проверка 0.22.0

1. Продолжить своё сохранение 0.21.0; проверить рюкзак, магазины AK/M4, дрона и его груз, производство, ферму, повреждения стен и пулемёты.
2. Сохраниться и перезагрузить страницу. Проверить те же предметы и числа.
3. Переключиться A → B → A; проверить имя слота, импорт/экспорт и резервную копию.
4. Создать новую игру в свободном слоте. Проверить стартовое состояние и сохранность прежнего слота.
5. Повторно открыть станок, печь, «Медицину», «Напитки», дрона и турель. Проверить закрытие снаружи без сквозного клика, перетаскивание и касания.
6. Проверить обычную вылазку, переход в подвал, дрона, зарядку, крафт и управление на телефоне.
