# LAST BASE 0.23.0 — результат Этапа 3

Выполнен весь Этап 3 «Обобщать системы по очереди» поверх принятой вручную 0.22.0. Работа шла последовательно: предметы / инвентарь / боеприпасы / оружие → враги → дрон / турели → destructibles / upgrades. После каждой части выполнен свой контрольный прогон. **Этап 4 «Ресурсы и загрузка» не начат.**

## Что изменено

- **Предметы и боеприпасы:** вместимость стопок и признак боеприпаса находятся в существующем `ITEM`. Несколько пушек могут использовать один ammo ID; совместимость в интерфейсе берётся из каталога оружия.
- **Оружие:** перезарядка, шум, оформление и совместимость съёмных магазинов читаются из `V09Craft.weapons`. Выбор и прицеливание не ограничены списком AK/M4. Физические магазины, патроны в экземпляре оружия и атомарность замены сохранены.
- **Враги:** прежние каталоги теперь ссылаются на один объект. Порядок появления и выбор обычной атаки / прыжка / взрыва определяются данными. Новый тип получает фактические модификаторы Дня X автоматически.
- **Дрон:** характеристики корпуса, батареи, груза, движения и стрельбы находятся в определении существующего предмета. Интервал 155 мс больше не зависит от AK. Тип и ID единственного физического дрона явно разделены; переносной предмет ссылается на тот же экземпляр.
- **Турели:** действующий модуль читает определение типа при выдаче, размещении, стрельбе, работе с патронами, снятии и сохранении. ID экземпляра сохраняется на всём пути; повтор одного экземпляра отклоняется.
- **Разрушаемые объекты:** общий расчёт HP, урона, ремонта и стадий повреждения используется существующими стенами/воротами/дверями. Доступны параметры armor/resistances, у текущих объектов они нулевые. Действия при разрушении остаются у прежних владельцев.
- **Улучшения:** общий источник пределов и стоимости; характеристики экипировки рассчитываются по таблицам. Станок работает с определением семейства предмета, включая турели с другим ID.

Новых предметов, врагов, пушек, дронов, уровней улучшения или разрушаемых объектов в игру не добавлено. Не менялись баланс, управление, расположение объектов, AI-маршруты, электроснабжение, производство и ферма. Отдельных исправлений старых игровых сценариев в этом этапе не заявляется.

## Сохранения и идентичность

**Формат существующих saves сохранён: `saveVersion: 1`, прежние схемы подсистем, поля, localStorage-ключи и пять слотов.** Изменены только метаданные релиза на 0.23.0 и допуск этой версии к загрузке.

Тип предмета не заменяет UID конкретной пушки/экипировки, `robotId` переносного дрона или `turretData.id` пулемёта. Старые записи турелей сохраняют прежний неявный тип. Поддержка явного `type` для будущего другого типа проверена изолированно и не добавляет поля в нынешние saves.

Индексные связи врагов и `targetIndex` дрона остаются совместимыми с прежними saves. Их перевод на постоянные сетевые ID не выполнялся. Готовность co-op/networking этим этапом не заявляется.

Сохранилось фактическое поведение Дня X, включая HP/урон/скорости ×1,5, ускорение атаки через cooldown ÷1,5, особые действия прыгуна/взрывника и прежнюю численность. Его не заменяли другим описанием события.

## Производительность

Принятая 0.22.0 и итоговая 0.23.0 измерены последовательно одним runner: одинаковые seed и состояния пяти сцен, Canvas2D 1280×800, DPR 1, 60 прогревочных и 180 измеряемых кадров на сцену. Состояния сцен совпали, ошибок консоли нет. Ниже — время update + draw в миллисекундах.

| Поверхность, день | 39.98 / 67.59 | 36.90 / 47.35 |
| Поверхность, ночь Дня X | 83.28 / 101.03 | 79.33 / 89.62 |

Во всех пяти сценах медиана и p95 в этом прогоне ниже контроля. Это не доказательство ускорения на устройстве: стенд работает на общем CPU, DOM моделируется, браузерный layout/compositing не измеряется. Значения нельзя переводить в FPS телефона.

Дополнительные замеры: save (20 повторов), медиана / p95 — 2,05 / 4,11 → 1,98 / 3,32 мс; load — 86,97 / 99,05 → 81,41 / 93,66 мс. Однократный старт JS и модели DOM: 559,65 → 589,69 мс; оставшееся ожидание декодирования изображений: 47,11 → 122,03 мс. Эти стартовые значения выросли в данном прогоне, но одиночный замер на общем стенде не отделяет влияние нагрузки и кэшей от кода. Загрузка ресурсов в Этапе 3 не изменялась.

RSS после старта: 600,37 → 600,58 МБ; в конце последней сцены: 525,32 → 526,99 МБ. Это память всего тестового процесса, включая Canvas2D, декодированные изображения и модель DOM, а не мобильного WebView.

Исходные измерения и сравнение: `qa/results/performance-stage2-control.json`, `performance-stage3.json`, `performance-stage3-comparison.json`. Повтор сравнения: `node qa/compare-performance.cjs`. Старые замеры сохранены отдельно; ручная проверка браузера/Telegram и телефона остаётся необходимой.
