# Этап 3 — обобщение существующих систем

Основа — принятая вручную 0.22.0. Результат — 0.23.0. Выполнены последовательно четыре внутренние части Этапа 3. Этап 4 «Ресурсы и загрузка» не начат.

## Где теперь находятся определения

| Область | Единственный источник и общая логика |
|---|---|
| Предметы, вместимость стопки, боеприпасы | `ITEM`, `itemStackLimit` в `core/world-inventory.js`; дополнения предметов остаются у прежних владельцев |
| Ручное оружие | `V09Craft.weapons` в `crafting/manufacturing.js`; `V010Combat` читает характеристики определения |
| Физические магазины | `V09Craft.magazineTypes`; прежний `V0162Magazines.TYPES` — ссылка на тот же объект |
| Враги | `V017Monsters.specs` и `V010World.TYPES` — один объект; `combat/monsters.js` |
| Дрон | `ITEM.drone014.drone`, прежний `V014Robots.state`, прежний модуль движения |
| Турели | `ITEM[type].turret`, прежние `V016Turret.guns` и операции размещения/переноса |
| Улучшения | `V010Combat.upgradeRules`, определения дрона/турели ссылаются на эти же правила; прежний станок `V0161Upgrade` |
| Экипировка | `V010Combat.equipmentStats`; индивидуальное определение может указать `stats` |
| Разрушаемые объекты | `V015Base.health`, прежние секции и `V018Build.structures`; никаких копий объектов |

## Предметы, оружие и магазины

Ключ `ITEM` и поле `item.type` определяют вид предмета. Поле `uid` определяет конкретную пушку или предмет экипировки. Перенос, выбор и перезарядка работают с экземпляром. Переключение между двумя одинаковыми пушками не объединяет их уровни или боезапас.

`ammo: true` и `stackMax` в определении патрона управляют его стопкой. Несколько пушек могут ссылаться на один ammo ID. Совместимые пушки в интерфейсе вычисляются из существующего каталога оружия.

Определение оружия содержит прежние характеристики и дополнительные параметры: `category`, `reloadMs`, `noise`, `heldStyle`, `visualRecoil`, `recoilLabel`, `magazineTypes`, `defaultMagazine`, `extendedMagazine`. `heldStyle` выбирает существующий рисунок оружия; новый уникальный рисунок всё равно требует собственного оформления. Новое оружие с существующей механикой добавляется в `ITEM` и `V09Craft.weapons`; подходящий рецепт добавляется в прежний каталог рецептов. Новые механики выстрела этим этапом не реализовывались.

Магазин остаётся физическим пустым предметом. После установки оружие хранит `magazineType` и `rounds`. Снятие возвращает компонент и патроны его калибра. При нехватке места операция полностью отменяется. Старое `modules.magazine` используется только на пути миграции старых сохранений. Новый Boolean-модуль вместо физического магазина не вводился.

Старый производственный payload `v09.crafting.magazines`, стартовый набор, исторические миграции, конкретные задания, рецепты и таблицы добычи сохраняют прежние конкретные ID. Это совместимость/состав контента. Активная перезарядка, совместимость компонентов и выбор оружия больше не ограничены списком AK/M4.

## Враги и фактический День X

Порядок появления определяется `spawnOrder`; исходная последовательность сохранена: normal → heavy → fast → leaper → bloater. `behavior` выбирает обычную атаку, прыжок или взрыв. Параметры специальных действий находятся в `leap` и `blast`. Новый тип с такой же механикой использует тот же код. Временные тестовые типы отсутствуют в поставляемой игре.

День X сохраняет фактическую механику 0.22.0: HP, урон, скорости ×1,5; интервал обычной атаки ÷1,5; прежние множители обнаружения, прыжков и взрыва; прежняя численность 48/96 с ограничением 144 и учётом настройки сложности. Это не замена поведения на другое описание события. Полученные характеристики кэшируются, а новый тип автоматически получает модификаторы. Общая будущая система мировых событий не создавалась.

Тип врага и временный ID актёра различаются. Существующие индексные связи в saves и `targetIndex` дрона сохранены: ID актёра не выдаётся за постоянный сетевой ID. Миграция всех врагов на сохраняемые ID и networking остаются за границами этапа.

## Дрон и турели

Параметры корпуса, контейнера, батареи, движения и стрельбы дрона вынесены в его существующее определение предмета. Интервал стрельбы 155 мс больше не считывается из AK. `type` и `instanceId` явно разделены; их старое одинаковое написание сохранено для совместимости. Переносной предмет ссылается на тот же экземпляр через `robotId`.

Сохранены один дрон, его режимы, маршруты, станция, зарядка, груз и правила команд. Фабрика нескольких дронов и тяжёлый боевой дрон не добавлялись.

Турель получает характеристики из `ITEM[type].turret`; `turretData.id` остаётся ID конкретного пулемёта. Общие операции умеют читать определение выбранного типа: выдача предмета, боезапас, стрельба, установка, снятие, улучшение, проверка дубликатов и save/load. Поставляемая игра по-прежнему содержит только существующий пулемёт. Старые записи сохраняют неявный тип hmg016 и прежний набор полей. Для будущего отличающегося типа код поддерживает явный `type`, не добавляя его в прежние записи.

## HP, ремонт и улучшения

Существующие стены, ворота и двери используют общие уровни HP, стоимости, ремонт и стадии повреждения. Общий расчёт урона допускает armor/resistances в определении; у всех текущих объектов они нулевые. Разрушение по-прежнему запускает прежние действия владельца: освобождение прохода, состояние двери, падение с разрушенной опоры и изменение геометрии.

Ремонт по-прежнему даёт 1000 HP/с, 1 бетон — 1000 HP, остаток смеси сохраняется. Улучшение требует полной прочности и прежних материалов. Новых разрушаемых объектов нет.

Станок усиления использует общую формулу стоимости и правило выбранного предмета. Уровни, запреты, потребление материалов и характеристики текущих уровней 0–5 сохранены. Возможность задать иной предел проверена только на тестовом определении. Десять уровней в игру не добавлены.

## Сохранения и воспроизводимость

`saveVersion` остаётся **1**; схемы подсистем, ключи localStorage, слоты и старые IDs не меняются. Новый номер релиза — 0.23.0. В сравнении полных сохранений с 0.22.0 исключается только `gameVersion`.

`qa/stage0/` и `qa/stage1/` сохранены. `qa/stage2/` содержит исполняемую принятую 0.22.0 и 25 контрольных saves, полученных её исполнением. Все saves стенда синтетические.

- `node qa/stage3-gate.cjs 1` … `4` — наборы проверок по внутренним частям. Отчёты выполненных последовательных gates содержат хэш сборки на тот момент.
- `node qa/systems.cjs 4` — проверки расширения через временные определения.
- `node qa/stage3-differential.cjs` — сравнение с принятой 0.22.0, 75 saves, вариантов характеристик и сценариев.
- `npm test` — весь regression suite.
- `npm run bench` — прежний стенд производительности.

Исторические контрольные хэши относятся к соответствующему этапу. Новый аудит и точный diff находятся в `qa/stage3-reference.json` и `docs/stage3-source.patch`.

## Ручная проверка

1. Продолжить свой save, сохранить и перезагрузить страницу; проверить слоты, экипировку, хранилища, производство и ферму.
2. Пострелять из AK/M4; снять, заменить и зарядить оба магазина; проверить операцию с полным рюкзаком.
3. Проверить обычных врагов и День X, особенно прыгуна, взрывника и атаки стен/дверей.
4. Упаковать/разместить дрона, проверить груз, боезапас, сопровождение, возвращение и зарядку.
5. Снять/установить пулемёт, загрузить патроны, проверить автоогонь и разрушение его опоры.
6. Повредить, отремонтировать и улучшить стену/дверь; усилить оружие, экипировку, модуль дрона и пулемёт.
7. Проверить касания, оба джойстика, окна и уменьшенный масштаб на телефоне.

Автотесты исполняют игру в VM с моделью DOM и Canvas2D. Они не заменяют проверку нативного браузера/Telegram WebView и телефона. Семь исходных MP3 отсутствуют, как и раньше. Asset paths, изображения, CSS и система загрузки не перерабатывались.
