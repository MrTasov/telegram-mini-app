# LAST BASE 0.24.0 — ресурсы и загрузка

Одна игра с прежними системами и PC/Mobile управлением. Этап 4 меняет организацию файлов и слой презентации; Этап 5 не начат.

## Где находятся ресурсы

| Путь | Назначение |
|---|---|
| `assets/manifest.json` | Единый каталог путей, размеров, crop и atlas metadata |
| `assets/icons/items/` | 45 PNG-иконок с понятными именами предметов |
| `assets/images/props/` | Мебель, станки, генератор и прочие объекты мира |

| `assets/images/crops/` | Изображения культур |
| `assets/images/drones/` | Изображение дрона |

## Как заменить обычную картинку

1. Найдите нужный файл по таблице или `assets/manifest.json`.
2. Замените его, сохранив **имя, расширение и папку**. Код игры менять и пересобирать не требуется.
3. Для максимально предсказуемого результата сохраните прозрачность, пропорции и расположение объекта внутри изображения.
4. Если меняется только разрешение, crop обычного изображения масштабируется относительно исходного размера. Если композиция объекта изменилась, скорректируйте `crop` в каталоге и выполните сборку.
5. Перезагрузите страницу. При старой картинке выполните полное обновление/очистку кэша сайта.

Примеры: `assets/icons/items/wood.png`, `assets/images/drones/companion.png`, `assets/images/props/workbench.webp`.

Этот этап не пересжимает тяжёлые исходные картинки и не меняет коллизии/размеры игровых объектов вслед за разрешением изображения.

## Как заменить атлас

Атлас — несколько кадров на одном листе. Для замены без пересборки сохраните размер листа и расположение/размер всех кадров. Имя, формат и путь тоже должны совпадать.

Если изменился лист, исправьте metadata в `assets/manifest.json` и выполните `npm run build`:

- `size`: ширина и высота всего листа;
- `layout: grid`: `columns`, `rows`, `frameSize`, `frameCount`, при необходимости отдельные `crops`;
- `layout: packed`: именованные прямоугольники `frames` и их `frameCount`;
- прямоугольник `{x, y, w, h}` задаётся в пикселях листа, начало координат — его левый верхний угол.

Враги используют 8 кадров: 4 движения и 4 атаки. Исходная сетка — 4×2, ячейка 384×512. Тела используют 3 варианта в сетке 3×1 с отдельными crop. Стены используют 3 именованных региона: `wall`, `corner`, `stairs`. Сборка проверяет эти контракты существующего renderer; тайминги, состояния атак и количество вариантов не менялись.

Размер реального атласа должен совпадать с metadata. Несовместимый лист не рисуется с неправильной обрезкой: игра сохраняет прежнее резервное отображение, а проверка сборки сообщает ошибку. Отсутствующая картинка также не вызывает повторные запросы на каждом кадре. После исправления файла перезагрузите игру.

## Как работает загрузка

`assets/manifest.json` → проверка `tools/assets.cjs` → сгенерированные данные `src/assets/manifest.js` → общий `GameAssets` → существующие `V011Art`, стены, иконки и аудиосистема.

Каталог включён в готовый `js/game.js`: отдельного сетевого запроса JSON при старте нет. На один Canvas-ресурс создаются один `Image` и один Promise загрузки. Картинки запрашиваются по необходимости; тела подгружаются вместе с соответствующим видимым врагом. Атласы высоких уровней стен не загружаются заранее.

DOM-иконки продолжают использовать обычные `<img>` с теми же стабильными URL. Переиспользование их сетевого кэша обеспечивает браузер; общий менеджер не гарантирует один объект декодирования между DOM и Canvas. Загрузка изображений не создаёт второй game loop, input listener или player и не попадает в save.

Обычное HTTP-кэширование изображений сохранено. Service Worker, случайные параметры URL, immutable-кэш для заменяемых картинок и обязательная предзагрузка всего каталога не добавлены. Политика сервера/CDN также влияет на обновление: замена файла не обновляет уже загруженный `Image` в открытой вкладке. Для кода и CSS сохранено версионирование URL по выпуску.

Семь исходных MP3 уже отсутствовали в принятой версии. Их отсутствие теперь явно указано в каталоге; лишние запросы к отсутствующим звукам убраны. При первом добавлении файла нужна сборка для обновления признака наличия. Декодированные звуковые буферы сохраняются на сеанс; существующая привязка к жесту пользователя остаётся.

## Проверки и сборка

Готовый архив уже содержит сборку; для размещения сайта Node.js не нужен. Для разработки нужны Node.js 20+ и тестовая зависимость `@napi-rs/canvas`:

```sh
npm ci
npm run assets
npm run build
npm run check
npm test
```

`assets` и `build` проверяют обязательные файлы, пути, ссылки каталога, размеры и layout атласов, frame count и crop. `test` дополнительно проверяет исходные SHA-256 изображений этого выпуска, декодирование всех файлов, HTTP-пути под префиксом проекта, пиксельное совпадение с 0.23.1, прежние saves и всю игровую регрессию. После намеренной замены арта исторические проверки SHA/pixel equality закономерно укажут на отличие; их эталон обновляют отдельным проверенным изменением.

Файлы `qa/stage0/`…`qa/stage3/` и `qa/controls-base/` — замороженные эталоны. Только стенд переводит их старые asset paths по `qa/asset-migration.json` на новые файлы с теми же байтами. Текущая игра такого перевода не имеет, поэтому проверка новых путей не скрывает ошибки.

## Ручная проверка

- Холодный запуск, затем повторное открытие на PC и телефоне.
- Первое появление предметов, дрона, станков, культур и всех типов врагов; переход в бункер и обратно.
- Кадры движения/атак, варианты тел и постепенное исчезновение.
- Все уровни стен, углы, лестницы, разрушенные участки.
- Иконки инвентаря, хранения, крафта, улучшений, быстрого доступа.
- AUTO/PC/MOBILE, мышь, touch, джойстики, Fire, Action, портретная/альбомная ориентация.
- Загрузка своих старых слотов, сохранение и повторная загрузка.
- Долгая сессия на телефоне: FPS, нагрев, память и первый заход в новую сцену.

Автотесты выполняются в VM с моделью DOM и настоящим Canvas2D. Они не заменяют настоящий браузер, Telegram WebView и телефон.
