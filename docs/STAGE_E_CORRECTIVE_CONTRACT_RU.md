# 0.36.1: corrective поверх Stage E

Исходная сборка: 0.36.0, runtime SHA-256
`7e147c04ddb67e03a4c62f7de554c1813987101a0ba59937132e2a51312b486a`.

## Domain и save

Формат 16, research schema 1 / contentRevision 1, migration 15→16 сохранены.
Research/Blueprint/type/instance ID, цены, источники, receipts и unlock mappings
не изменены. Изменено только условие предварительного исследования у M4 и
эффективности производства: отдельное изучение изготовления станций больше
не требуется. Для M4 нужен чертёж, а для обслуживания Scout — чертёж и
установленная станция дрона. Физический работающий командный центр обязателен
для авторитетных Research-команд, как и ранее.

Ни Research, ни Blueprint не создают предмет. Производство, реальные слоты
рюкзака, размещение и перенос того же экземпляра остаются у прежних владельцев.
В UI определения содержат локализуемый `requirementLabel`; внутреннее условие
проверяет существующий GameConditions, а команду — ResearchDomain. Клиент
не изменяет progression state напрямую.

## Навигация

Command Core владеет общей историей страниц раздела (до 32 записей) и переходов
между разделами по внутренним ссылкам (до 16). Выбор основной вкладки завершает
межраздельный возврат; сама вкладка сохраняет последнюю допустимую страницу.
Back сначала возвращает страницу, затем раздел. Escape использует тот же Back
перед закрытием окна. Переключение комнаты в Base Control заменяет текущую
страницу, а не наполняет историю каждым выбором комнаты.

История, scroll position, фильтр и подробности — session UI state. Они не
входят в GameSave; очистка при выходе с Level 1 и при restore сохранена.
Remote использует тот же Base Control и не получает доступ к Research.
Журнал на HUD остаётся отдельным, без operational команд командного центра.

Одинаковые узлы и обработчики Research работают на PC, mobile portrait и
landscape. Адаптивные стили меняют размеры, не состав функций. Четыре основные
вкладки размещены в четырёх колонках. Внешняя панель зависит только от viewport
и safe areas; прокрутка ограничена content area. Учтены safe areas сверху,
снизу, слева и справа; SDK Telegram в обычной вкладке сам по себе не означает,
что игра открыта внутри Telegram.

## Аудио

Mixer, исходные WAV, gains, voice limits, контакты анимации, зоны и 10 Hz observer
сохранены. После closed-context старый граф освобождается; следующий разрешённый
запуск создаёт новый контекст и подключает к нему выход и animation gains.
Декодированные AudioBuffer переиспользуются.

resume вызывается синхронно из доверенного pointer/click/key события до ожидания
загрузки. После ранее выполненного жеста focus/pageshow/возврат из hidden
пытается восстановить звук. Отказ браузера сохраняется; следующий настоящий
жест повторяет попытку. До первого жеста focus не создаёт контекст. Синтетическое
событие с isTrusted=false не разблокирует звук.

Загрузка ограничена двумя задачами, первыми загружаются звуки UI. Ошибки fetch
и decode видны в диагностике; fetch прерывается по тайм-ауту 12 с. После паузы
повторяются только отсутствующие буферы. Settings → «Проверить звук» использует
тот же mixer и отображает готовность/загрузку/ошибку/mute. Значение 0 сохраняет
mute; некорректное сохранённое значение не превращается в случайный mute.

GameAudio.inspect() предоставляет локальную диагностику состояния контекста,
master/output gain, отсутствующих буферов и ошибок. Это не gameplay-save,
не телеметрия и не новый сетевой сервис.
