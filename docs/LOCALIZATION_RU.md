# Localization EN/RU — Этап 5

По умолчанию игра открывается на English. В Settings → LANGUAGE можно выбрать Русский. Настройка `last_base_language_v1` хранится отдельно от пяти игровых слотов и не включается в экспорт прогресса. При недоступном localStorage выбор работает до перезагрузки; предупреждение показывается в Settings и не записывается в игровой журнал.

## Структура

| Путь | Назначение |
| --- | --- |
| `locales/en.json` | Английские тексты по стабильным ключам |
| `locales/ru.json` | Русские тексты с теми же ключами |
| `locales/manifest.json` | Язык по умолчанию, список языков, Intl locale и имена файлов |
| `locales/legacy.json` | Соответствие прежних канонических подписей ключам |
| `locales/sources.json` | Контекст старых подписей: исходный текст и места использования |
| `src/i18n/runtime.js` | Перевод, параметры, формы множественного числа, форматирование, привязки вывода |
| `src/i18n/settings.js` | Переключатель языка в существующих Settings |
| `tools/locales.cjs` | Валидация каталогов и воспроизводимая генерация |
| `src/i18n/catalogs.js` | Сгенерированные каталоги, включённые в готовый bundle |

Каталоги включаются в сборку синхронно до создания интерфейса. При смене языка нет сетевого запроса, перезапуска игры или пересоздания окон. Нет MutationObserver, дополнительного game loop или второго набора обработчиков управления. Кэш готовых строк ограничен 1024 записями, кэш Intl — 64. Привязки DOM используют WeakMap; удалённые окна не удерживаются системой переводов.

## Новые тексты

Добавляйте осмысленный ключ одновременно в оба JSON-файла:

```json
"example.result": "Received: {count}"
```

Для немедленного вывода используйте `I18n.t(key, params)`. Для DOM, который должен сразу реагировать на переключение языка:

```js
I18n.bind(label, 'example.result', {count: 3});
// bind возвращает функцию отписки для временной привязки.
```

Для часто обновляемого поля:

```js
I18n.assign(label, 'textContent', I18n.message('example.result', {count: 3}));
```

`I18n.message` — временное представление текста с ключом и параметрами. Оно предназначено для слоя вывода. Не помещайте его в GameState или собственные поля сохранения. Существующий маршрут `message → journal` перед записью получает исторический канонический текст через `I18n.canonical`; локаль не меняет данные журнала.

Параметры вставляются как данные и повторно не переводятся. Для пользовательской части старой составной строки используйте `I18n.verbatim(name)`. Используйте textContent для пользовательского текста, не вставляйте его напрямую в HTML.

Плюральные формы: объект с `one`, `other`, а для RU также `few` и `many`; выбор по `params.count` через Intl.PluralRules. `I18n.number` и `I18n.date` дают готовую строку, `I18n.numeric` и `I18n.dateText` сохраняют форматирование при живом переключении DOM. Canvas получает `I18n.text` перед рисованием и измерением текста. Сортировка инвентаря по запросу пользователя использует переведённое имя и Intl.Collator.

## Совместимость старого кода и saves

Старые подписи остаются каноническими в определениях и исторических полях saves. Адаптеры DOM/Canvas сопоставляют их стабильным ключам `legacy.*` в тех же каталогах. Выбор длинной фразы и границы слов обрабатываются в слое представления; текст не используется для определения игровых действий. Условные проверки старого UI, которые читали title/textContent, обращаются к исходной подписи через `I18n.source`.

Это намеренный переходный слой: не требуется переименовывать предметы внутри старых save payloads. Новое содержимое следует добавлять через осмысленные ключи, а не копировать русские строки в новые UI-функции. `sources.json` помогает найти контекст старого ключа.

- ID предметов, типов монстров, рецептов и физических экземпляров не переводятся.
- Название LAST BASE, международные модели и калибры сохраняют международное написание. Старое визуальное `АК-74` выводится как `AK-74`; `5,45` в технических подписях — как `5.45`. Сохранённые ID не меняются.
- Имена сохранений, меток и дрона остаются пользовательскими данными. Старое русское имя поэтому может отображаться в английском интерфейсе.
- Стандартные подписи ящиков переводятся; изменённые названия сохраняются. Старый формат не отличает введённое пользователем имя, полностью совпадающее со стандартным именем того же ящика: такая подпись отображается как стандартная.
- Переключение языка не меняет движение, прицеливание, огонь, обработку взаимодействий и длительность добычи.

## Добавление языка

Создайте `locales/<id>.json` с полным набором ключей и параметров, добавьте запись в `manifest.json`, выполните `npm run build` и `npm test`. Settings создаёт варианты из manifest. Код simulation менять не требуется. Для отсутствующего ключа во время исполнения используется английский fallback, а неизвестный ключ возвращается без исключения. Release validator отклоняет неполные каталоги и несовпадающие параметры.

## Ручная проверка

Проверьте PC и телефон: Settings → EN/RU, возврат после перезагрузки, длинные подписи рецептов и окна в портретной/альбомной ориентации. Откройте карту, выберите свободную точку и нажмите Go here / Идти сюда. У края мира запустите добычу: шкала должна оставаться над персонажем при движении камеры и масштабировании.
