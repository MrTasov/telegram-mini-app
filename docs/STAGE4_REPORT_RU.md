Она восстановлена из принятого архива `LAST_BASE_0.23.1_PC_Mobile_Controls_GitHub.zip`, SHA-256 `4e41640ee5207fa46782d95639a1433b817aaab6fd037540ea161b8f60f18d93`. ## Что изменилось

- 99 изображений получили понятные постоянные пути. Все файлы сохранили исходные байты и SHA-256; сжатие, качество и внешний вид не менялись.
- `assets/manifest.json` стал единственным каталогом путей, исходных размеров, crop и раскладки атласов. Каталог проверяется при сборке и включается в `js/game.js`, без дополнительного JSON-запроса при запуске.
- `GameAssets` хранит один Canvas Image и один Promise на ресурс. Загрузка по потребности, декодирование перед готовностью, проверка размеров атласа и обработка ошибок отделены от game state.
- Существующие `V011Art`, стены, иконки и аудиосистема используют каталог. Враги подгружают соответствующие изображения тел вместе с собственным листом. Атласы высоких уровней стен запрашиваются при необходимости.
- Обычный файл можно заменить по тому же имени/формату/пути без изменения game logic и без пересборки. Crop масштабируется при изменении разрешения обычного изображения. Атлас требует совпадающей раскладки либо обновления metadata и сборки.
- Семь MP3 отсутствовали ещё в Stage 0 и принятой 0.23.1. Теперь это явно optional-ресурсы; отсутствующие эффекты не запрашиваются. Имеющиеся аудиофайлы загружаются после жеста пользователя с проверкой HTTP-статуса и `cache: no-cache`.

Изменения runtime ограничены ресурсами/отрисовкой и metadata выпуска. PC/Mobile input, player, AI, характеристики оружия, баланс, поведение дрона, производство, энергия, улучшения и игровая логика сохранены. CSS и исходники input остались байт в байт прежними. В save меняется номер выпуска; `saveVersion: 1`, schema, ключи storage, порядок адаптеров и пять слотов сохранены. Новый номер 0.24.0 добавлен в существующую проверку допустимых выпусков.

## Загрузка и память

Мобильная инициализация стенда: 390×844, DPR 1, MOBILE. Счётчик фиксируется после инициализации тестовой страницы до последующих кадров; позднее новые видимые объекты загружаются по необходимости.

| Метрика | 0.23.1 | 0.24.0 |
|---|---:|---:|
| Запрошенные Canvas-изображения | 50 | 2 |
| Их исходные файлы, МБ | 20.55 | 1.02 |
| Оценка декодированного RGBA, МБ | 128.66 | 7.18 |
| Уникальные ресурсы Canvas + DOM img | 68 | 20 |
| Их исходные файлы, МБ | 21.39 | 1.86 |
| Локальная инициализация + начальное декодирование, мс | 489.09 | 422.75 |
| RSS процесса стенда после старта, МБ | 332.00 | 141.76 |

В desktop-размере стенда текущая инициализация запрашивает 7 Canvas-картинок; исходная версия также запрашивала 50. DOM-иконки не переведены на новый механизм: набор стартовых 18 URL совпал. Браузер сам переиспользует HTTP-кэш между DOM и Canvas; менеджер не обещает один объект декодирования для них обоих.

Это **не замер мобильной сети или памяти телефона**. RGBA рассчитана как ширина × высота × 4, DOM-картинки в модели не декодируются, RSS включает VM/Canvas/стенд. В долгой сессии посещённые ресурсы остаются закэшированными; отдельная система вытеснения не добавлялась. После пяти тёплых сцен RSS составил 522,44 → 526,03 МБ (+0,69%) — близкие значения, не доказательство расхода памяти на устройстве.

Отчёты: `qa/results/loading-stage4-baseline.json`, `loading-stage4.json` и `performance-stage4-comparison.json`.

## Кэш, известные ограничения и ручная приёмка

- URL картинок стабильны. Случайные query-параметры, Service Worker и обязательный immutable-кэш не добавлены. После замены файла может понадобиться полное обновление страницы; поведение зависит и от сервера/CDN.
- Семь optional MP3 перечислены в `assets/audio/effects/README_RU.md`. Они не выданы за восстановленные файлы. При первом добавлении/удалении эффекта нужна сборка, при замене уже включённого файла по прежнему пути — нет.
- Ошибочный атлас не рисуется неверным crop. До завершения первой загрузки может быть видно прежнее резервное отображение; тела запрашиваются вместе с видимым врагом. На медленной сети проверьте первое появление объектов и переходы.
- Изображения не пересжимались: тяжёлые оригиналы сохранены ради полного визуального соответствия. Отдельная оптимизация качества/разрешения в этот этап не включена.

На GitHub загружайте **распакованное содержимое** `LAST_BASE_0.24.0_Stage_4_GitHub.zip`; сборка уже готова. Для сайта нужны `index.html`, `js/`, `styles/`, `assets/`. Сохраняйте прежний адрес сайта для доступа к прежнему localStorage.

Для ручной проверки: холодный/повторный запуск, поверхность ↔ бункер, первое появление арта, дрон/станки/турели/хранилища, все виды врагов и тел, уровни стен, иконки, PC/MOBILE и ориентация, старые слоты и длительная сессия телефона. Подробный список — в `docs/ASSETS_RU.md`.
