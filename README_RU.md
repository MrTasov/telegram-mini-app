# LAST BASE 0.22.0 — Stage 2

Выполнен этап «Упорядочить состояние и сохранения» поверх принятой 0.21.0. Готовая статическая версия для GitHub Pages и Telegram Mini App. Этап 3 не начат.

## Запуск и загрузка на GitHub

Распакуйте архив и загрузите его содержимое в репозиторий. Для сайта нужны вместе `index.html`, `js/`, `styles/`, `assets/`. Для полного проекта сохраните также `src/`, `tools/`, `qa/`, `docs/` и `package.json`. Сам ZIP загружать вместо распакованных файлов не нужно.

GitHub Pages использует уже собранный JS; Node.js на сайте не требуется. Адрес сайта и ключи хранилища сохраняются. Старые сохранения загружаются автоматически.

Локальный запуск:

```sh
python3 -m http.server 8080
```

Откройте `http://localhost:8080`. Разные адреса сайта имеют отдельное хранилище браузера; для переноса используется существующий экспорт/импорт saves.

## Исходники

- `src/` — 56 JS-секций, порядок в `src/manifest.json`.
- `src/state/` — живые представления владельцев состояния и служебное состояние saves.
- `src/save/` — формат, проверяемый реестр, старые миграции, слоты и финализация.
- `styles/base.css`, `assets/` — прежний CSS и 99 изображений, побайтно сохранены.
- `js/game.js`, `js/game.js.map` — готовая сборка и карта исходников; редактировать нужно `src/`.
- `docs/STAGE2_RU.md` — архитектура, границы этапа и ручная проверка.
- `docs/REPORT_RU.md` — результаты и измерения.
- `docs/stage2-source.patch` — точные изменения относительно принятой версии.
- `qa/stage0/`, `qa/stage1/` — контрольные данные. Это синтетические saves для тестов.

Сборка без дополнительных зависимостей:

```sh
node tools/build.cjs
node tools/build.cjs --check
```

Сохраняется один обычный скрипт с прежним порядком исполнения. Система сохранений использует именованные адаптеры; игровой цикл и существующие API продолжают работать как раньше.

## Проверки

Для тестов нужен Node.js 20+ и тестовая зависимость `@napi-rs/canvas` 0.1.100:

```sh
npm install
npm test
npm run bench
```

`npm test` запускает все прежние регрессии Stage 0, взаимодействия Stage 1, saves, сравнение баланса, новые проверки состояния/слотов и сравнение полного save payload с принятой 0.21.0. Сводка: `qa/results/summary.json`.

`npm run bench` использует те же пять сцен, часы, seed, прогрев и Canvas-readback, что и Stage 0/1. Это локальный стенд, не FPS телефона. Зафиксированные результаты прошлых этапов находятся в `qa/stage0/reports/performance.json` и `qa/stage1/performance.json`.

Стенд моделирует DOM/события и исполняет реальный игровой код с Canvas2D. Он не заменяет ручную проверку в браузере и Telegram WebView. Семь MP3 отсутствовали в исходном Stage 0; новых отсутствующих путей нет. Список и ограничения указаны в отчёте.
