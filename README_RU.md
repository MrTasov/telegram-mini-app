# LAST BASE 0.21.0 — Stage 1

Готовая статическая версия для GitHub Pages и Telegram Mini App. Исправлены interaction-баги версии 0.20.0, затем выполнен только этап «Безопасно разделить код». Этап 2 не начат.

## Запуск и загрузка на GitHub

Распакуйте архив. В корне сайта должны оказаться `index.html`, папки `js/`, `styles/` и `assets/`. Замените их вместе: один новый `index.html` без остальных файлов работать не будет.

Для полного проекта загрузите также `src/`, `tools/`, `qa/`, `docs/` и `package.json`. GitHub Pages запускает уже собранные файлы; Node.js и npm на сайте не нужны. Сам ZIP загружать в репозиторий вместо файлов не нужно.

Локальная проверка через HTTP:

```sh
python3 -m http.server 8080
```

Откройте `http://localhost:8080`. Сохранения привязаны к origin браузера: локальная копия и опубликованный сайт используют разные хранилища. При обновлении существующего сайта адрес и ключи сохранений остаются прежними.

## Где теперь редактировать код

- `src/` — 51 исходный JS-файл, сгруппированный по областям игры.
- `src/manifest.json` — точный порядок исходных блоков.
- `styles/base.css` — прежний статический CSS, перенесённый без изменения правил и порядка.
- `index.html` — HTML оболочка, HUD и исходные окна.
- `js/game.js` — результат сборки; вручную его не редактировать.
- `js/game.js.map` — карта исходников для отладки в браузере.
- `assets/` — прежние 99 изображений с неизменными путями и содержимым.
- `qa/` — проверки, контрольные сохранения Stage 0 и отчёты.
- `docs/STAGE1_RU.md` — причины исправлений, границы этапа и ручная проверка.

После изменения исходников:

```sh
node tools/build.cjs
node tools/build.cjs --check
```

Сборка только соединяет исходные блоки в прежнем порядке. Нет минификации, транспиляции, npm-зависимостей для сборки, React или Vite. Выполнение остаётся одним обычным скриптом: это сохраняет hoisting, общие переменные и цепочки существующих расширений. Переработка владения состоянием и этих связей относится к следующим этапам.

Старый `source/build.py`, собиравший HTML поверх версии 0.19.1, не используется и не входит в рабочую цепочку. Единственный источник игрового JS — файлы из `src/manifest.json`.

## Проверки

Для тестов нужен Node.js 20+ и закреплённая зависимость Canvas; она используется только стендом:

```sh
npm install
npm test
npm run bench
```

`npm test` запускает сборочную проверку, все 477 прежних утверждений Stage 0, новые сценарии взаимодействий, совместимость 25 контрольных saves и сравнение характеристик. Результат находится в `qa/results/summary.json`. Контрольные saves синтетические: не импортируйте их поверх своего прогресса.

`npm run bench` использует те же пять сцен, seed, часы, прогрев и Canvas-readback, что и Stage 0. Это показатели локального стенда, а не FPS телефона или браузера. Предыдущие показатели лежат в `qa/stage0/reports/performance.json`.

Стенд моделирует DOM и события, но не заменяет проверку нативного браузера, Telegram WebView и реального телефона. Семь MP3 отсутствовали уже в исходном комплекте Stage 0; их список сохранён в отчётах. Новые аудиофайлы и новые игровые механики этим этапом не добавлялись.
