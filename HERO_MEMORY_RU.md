# LAST BASE 0.41.0 + исправление памяти героя (Claude)

**Как применить:** распаковать `LAST_BASE_0_41_0_Stage_I2_GitHub.zip`, затем распаковать поверх него `LAST_BASE_0_41_0_hero_memory_PATCH.zip` с заменой файлов (53 файла). Результат — новая принятая основа для следующих этапов.

Основа — `LAST_BASE_0_41_0_Stage_I2_GitHub.zip` без изменений логики I2. Версия игры и формат сохранений не менялись (0.41.0, Save Format 21).

## Проблема
Проверка памяти в отчёте 0.41.0 (`memory.characterAtlasesWithin40MiB`, `cache.sharedViewsLoadedOnceNoPerFrameImages`) показала 184 МиБ RGBA-атласов персонажей. Из них 147 МиБ — 42 листа нового героя (сетка 6×4 кадров с большим пустым полем). Листы грузились лениво, но никогда не выгружались, поэтому за долгую игру со сменой предметов память росла.

## Что сделано
1. **Листы героя перепакованы.** Каждый кадр обрезан по непрозрачным пикселям (+1 px поля) и плотно уложен в атлас (`layout: "packed"`, для каждого кадра `x,y,w,h` в атласе и `ox,oy` — место внутри исходной клетки). Картинка кадра та же: собрана из исходных рендеров, в игре попиксельно совпадает с прежней (средняя разница < 1,2/255, это сжатие WebP).
   - Все 42 листа: **147,0 → 52,0 МиБ** RGBA. Файлы: 3,32 → 3,65 МБ.
2. **Выгрузка листов предметов.** У героя свой небольшой кэш листов (`src/render/hero.js`):
   - базовые листы (стоит/идёт/бежит, 2,9 МиБ) — в общем `GameAssets`, не выгружаются;
   - листы предмета грузятся, когда предмет взят в руки, и освобождаются через 60 с после того, как его убрали; листы предмета в руках не выгружаются никогда;
   - пока лист предмета заново загружается, герой рисуется с базового листа (без мигания старым персонажем).
   - Одновременно в памяти: база + предмет в руках + (до минуты) предыдущий предмет — худший случай **27,4 МиБ** героя вместо 147.

## Изменённые файлы
- `assets/atlases/player/hero/*.webp` (42) — упакованные листы.
- `assets/manifest.json` → `src/assets/manifest.js` (сгенерирован `tools/assets.cjs`) — описание упакованных кадров.
- `src/render/hero.js` — рисование упакованных кадров, свой кэш с выгрузкой, запасной базовый кадр.
- `js/game.js`, `js/game.js.map`, `js/build-info.json` — пересборка `node tools/build.cjs`.
- `qa/hero-memory.cjs` — **новая** проверка: упаковка всех 42 листов, бюджеты памяти героя, наличие выгрузки.
- `qa/stage-i2-source-reference.json` — хэши принятых файлов героя обновлены на новые (44 файла: листы, `assets/manifest.json`, `hero.js`).
- `qa/assets.cjs`, проверка `lazy.noDuplicateCanvasRequests` — уникальных запросов по-прежнему ровно 198; допускается один повтор только для листа предмета, который кэш героя запросил до принудительной загрузки всех картинок в тесте.
- `release_manifest.json` — хэши и размеры обновлённых файлов, runtime SHA-256.

`src/assets/resources.js`, `src/render/actors.js`, логика I1/I2, WorldClock, Save/Load, Defense, звук и интерфейс **не менялись**.

## Проверки
- Полный набор из отчёта 0.41.0 (44 группы) + stage-i2, stage-i2-combat, stage-i2-contract, character-animation, player-visual-fix: результаты **совпадают** с исходной 0.41.0 (прежние известные падения те же, новых нет).
- `qa/hero-memory.cjs`: 6/6.
- Игра в Chromium (телефонный экран 430×900, DPR 2): стоит, идёт, стреляет с AK, топор, пульт, удочка — совпадает с прежним видом; после 70 с с удочкой листы AK/топора/пульта выгружены, при повторном взятии AK загружены заново; ошибок в консоли нет.
- Старые проверки с бюджетом 40 МиБ на всех персонажей вместе (`memory.characterAtlasesWithin40MiB`, `cache.sharedViewsLoadedOnceNoPerFrameImages`) по-прежнему не проходят: они считают все атласы сразу и не учитывают ленивую загрузку; зомби и старый модульный персонаж уже занимают 36,8 МиБ. Эти frozen-проверки не менялись; актуальный бюджет героя проверяет `qa/hero-memory.cjs`.
- На реальном телефоне не проверено.
