# LAST BASE 0.40.2 — Performance & Gameplay Corrective


Основа: точный принятый ZIP 0.40.1 Developer / QA поверх 0.40.0 I1. I2, Signal/Threat, Level 2 и другие стадии не начаты. Существующий DEV/QA сохранён.

## Границы проверки


Замеры выполнены на CPU стенда с V8 и настоящим Canvas2D (`@napi-rs/canvas`), оригинальными игровыми изображениями и исполняемым runtime. DOM, WebAudio и ввод моделируются. Chromium/WebKit и физический телефон/Telegram в этой среде недоступны. Эти результаты **не являются мобильным FPS** и не доказывают, что на телефоне теперь удерживаются 60 FPS.

У каждого сценария 180 кадров с шагом симуляции 16,667 ms; первые 60 — прогрев, последние 120 — измерение update + AudioWorld/render/Canvas flush. Выводятся median/p95/mean. Один процесс на сценарий, timeout 90 секунд: зависший сценарий записывается как limitation, а не блокирует упаковку. Профили V8 включают прогрев. Отдельные instrumented-запуски нужны только для стоимости separation, их frame time не смешивается с основным сравнением.

## Изменения


- Удалены Player shotVisuals, построение сегментов и два старых tracer stroke. Физические пули, попадания, урон и лёгкая вспышка остались. Линии турелей этим требованием не затрагивались.
- Задержка AK изменена с 155 до 155 / 1,3 ≈ 119,23 ms. Остальные характеристики сохранены. Число выстрелов за короткое окно дополнительно зависит от квантования кадров и перезарядки.
- Hammer использует существующие улучшения 0–5: 5/7/10/12/13/15% Max HP за фактический удар. Удар анимации, звук и ремонт используют один cycle/impact. Стоимость остаётся 1000 HP за бетон; остаток оплаченного ремонта сохраняется. При нехватке материала восстанавливается только оплаченное HP. Высокоуровневая стена 100000 HP требует 100 бетона и на Lv.0, и на Lv.5.
- Automatic/Heavy можно установить во дворе либо на подходящей целой внешней стене. Это прежние реальные instances и Inventory/Placement/Pick Up. Поддержаны запреты критических проходов, других объектов, поворот, сохранение mount/transform/HP/ammo и падение при разрушении опоры. Наземная турель не стреляет через целую стену; настенная пропускает свою опорную стену, но проверяет остальные препятствия. LOS проверяется и при выборе цели, и при выстреле.
- Intro вынесено из `#game` непосредственно в `document.body`: прежний CSS скрывал родителя Intro вместе с HUD. Сохранены contain 16:9, верхний слой, полупрозрачный Skip и safe areas. Видеофайл не менялся. Continue не запускает Intro.
- DEV показывает AI, render, off-zone AI ms и число пуль/эффектов рядом с существующими FPS/update/enemies/turrets. Таймеры включаются только в DEV; данные не входят в save.

## Что было дорого → что изменено


| Участок | Изменение | Ограничение |
|---|---|---|
| Повторные обходы врагов для каждого шага пули и поиска турели | Общий spatial broad phase с повторно используемыми buckets; точный narrow phase и исходный порядок первого попадания сохранены | Это индекс, не вторая симуляция |
| Zombie separation | Повторное использование buckets существующего spatial grid и пустого списка | Grid уже существовал; не заявляется как новая система |
| Blocker/raycast и проходимые стены | Числовой ray/AABB без временных массивов, дешёвый bounds reject; кеш списка и точного неизменившегося запроса по geometryRevision | Любое изменение позиции/геометрии инвалидирует соответствующий результат |
| Поиск пролома | Кеш списка открытых/сломанных секций по geometryRevision | Решение и движение врага остаются прежними |
| Equipment damage/ammo | Полная валидация сохраняется, но клонируется/замораживается только изменённая запись | Атомарность и authoritative commands сохранены |
| Физические footprints / defense registry | Кеш неизменившейся геометрии и списка записей | HP/ammo не требуют перестроения геометрии |
| Рендер устройства/света | Один snapshot power allocation на синхронный draw | Между кадрами/командами питание не кешируется |
| Повторный downscale атласов и составных слоёв Player | Ограниченный LRU raster cache, максимум 96 записей / 12 MiB RGBA | Исходные атласы, позы, анимации, тени и число врагов не отключены |
| Мини-карта | Фильтрация маркеров по видимой области до лишней обработки | Состояние exploration/POI не изменено |

Активный off-zone бой не замедлен искусственно. Для эквивалентного урона и расхода боеприпасов сохранены текущие combat ticks. Уже существующая I1 cadence для далёких неактивных врагов сохранена. Ускорены повторные геометрические/поисковые операции; невидимая Surface по-прежнему не рисуется в Bunker. Новых фоновых владельцев simulation нет.

## Корректность и saves


Save Format **20** сохранён. Hammer использует существующие level/UID поля; mount — существующие settings и transform. При capture предметы нормализуются до копирования общего snapshot, чтобы ленивое присвоение UID молоту не меняло состояние при отклонении некорректного save. Дробная погрешность 7% устранена вычислением через целый процент; бесплатного округления расхода нет.

Исторические тесты 1000 HP/сек и delay AK=155 обновлены только для явно утверждённых новых требований. Замороженные исходные fixtures не переписаны. Сравнения прочих характеристик, ресурсов и состояния остались строгими. Отдельно проверены все Hammer levels, стоимость/partial credit/save/load, двор→Hold Pick Up→стена, сохранение instance ID, grid против линейного первого попадания, Intro и DEV.

Дифференциальный бой до/после: Surface, Bunker, возврат на Surface; 240 update, Save/Load на шаге 90. Сравниваются реальные HP/позиции/состояния врагов, стены, оборудование, cooldowns, ammo, fuel, battery и HP Player. В каждом сценарии были настоящие попадания турелей и повреждение стены. Совпадение результата не подменяется количеством визуальных эффектов.

Native Canvas: сравнены 113 поз Player с исходным renderer; проверены потери alpha/обрезание и лимит кеша. Пример находится в `qa/results/perf-actor-comparison.png`. Это проверка отдельных изображений, **не визуальная приёмка браузерного интерфейса**.

### Что осталось дорогим

Направленный свет/тени и нативная отрисовка продолжают занимать заметную долю времени. Они не отключены. Тяжёлая сцена не стала гарантированно укладываться в 16,7 ms; численные улучшения стенда не заменяют проверку на телефоне. Кеш спрайтов меняет повторную растеризацию на ограниченную дополнительную память (до 12 MiB). `heap` в JSON — JS heap процесса до/после GC; он не включает полную память изображений/GPU и не выдаётся за RAM телефона.

### Сохранённые серии и ограничения

- `perf-before-first-series.json`: исходное профилирование до оптимизации; все его результаты сохранены.
- `perf-after-first-series.json`: первая серия candidate, часть пересеклась с targeted QA rechecks; не использована как итоговое изолированное сравнение.
- `perf-before.json`, `perf-after.json`: полная итоговая изолированная пара, 15 сцен.
- `perf-pilot.json`: три промежуточных сценария раннего runtime, не финальные цифры.
- `perf-before-short-initial.json` и `perf-before-initial-fixture.json`: первоначальные короткие/неполные fixtures; в первом M4 успевал только начать reload, во втором был исправлен аргумент DEV выдачи Buildable. Они сохранены как история измерений.
- `perf-*-detail.json`: инструментированная стоимость separation и V8 profiles; frame time содержит overhead инструмента.
- `perf-subsystems.json`, `perf-comparison.json`: развёрнутые результаты, p95/mean/heap/состояние боя.
- В `perf-initial-pass` / `perf-intermediate-pass` сохранены промежуточные неуспешные/смешанные по runtime прогоны. Выпуск опирается исключительно на финальный `summary.json`, где runtime неизменен.
