# LAST BASE 0.40.1 — Developer / QA Mode

Основа — принятая LAST BASE 0.40.0 Stage I1. Это отдельное дополнение для ручной проверки; I2, Signal/Threat, Level 2 и Farm/Animals не добавлены. Существующая off-zone simulation не переписана.

## Открытие и безопасность

В запущенной игре откройте Settings и нажмите номер версии шесть раз подряд (между нажатиями — менее четырёх секунд). Откроется компактная RU/EN консоль. Само открытие ничего не выдаёт и не меняет progression.

Нажмите «Создать тестовую копию». Текущий мир копируется в свободный слот сохранения; исходный слот остаётся нетронутым. Если все пять слотов заняты, включение отклоняется: сначала освободите ненужный слот обычными средствами меню. Уже помеченный мир можно включить повторно без дополнительной копии.

Копия постоянно помечена DEV/TEST, включая списки сохранений и переименование. Выключение панели не превращает тестовый мир в обычный. После загрузки DEV-команды и ускорение выключены; включите их снова вручную. Загрузка обычного сохранения сбрасывает тестовое состояние. Это инструмент разработки, не защита от пользователя, редактирующего JavaScript через консоль браузера.

## Функции

- Время: +1 час, +6 часов, +1 день, переход вперёд к выбранному дню, следующая ночь и следующий Day X; ×10, ×50, MAX, остановка задания.
- Враги: 1/10/25/50, существующие типы normal/heavy/fast/leaper/bloater и смешанная группа; обычная тестовая атака — 25 смешанных, тяжёлая — 50 heavy.
- Ресурсы: реальные позиции игрового каталога, +10/+100/+1000; учитываются вместимость Inventory и фактически добавленное количество.
- Оборудование: существующие buildable types создаются как реальные упакованные instances в Inventory. Далее работает обычное Placement; ограничения единичных станций сохранены.
- Player/Base: лечение, Fuel Tank, Battery, восстановление питания через существующий Generator, ремонт базы, повреждение/разрушение выбранной стены.
- Progression: существующие Chapter, Research, Blueprint и события. Research использует доменные команды, реальные требования и receipts; необходимые тестовые условия выполняются в копии. Unlock не выдаёт бесплатный предмет. Для некоторых исследований тестовый переход завершает Chapter 1.
- I1 STRESS TEST: на Surface создаёт до трёх реальных турелей (две Automatic и одну Heavy), размещает только в валидных позициях, снабжает боезапасом/питанием и запускает нападение 50 врагов. Можно обычным способом уйти в Bunker и наблюдать последствия по возвращении.

При недостатке места стресс-сценарий сообщает фактический результат; неустановленное оборудование остаётся в Inventory. Он не телепортирует Player и не обходит collision/critical-route validation. Существующие базовые ресурсы, предметы и combat systems используются напрямую; отдельной DEV-симуляции нет.

Тестовые атаки используют существующую механику осады Day X. Принудительное событие сохраняется в тестовом мире даже после отключения консоли; кнопка возврата к календарю снимает override. Очистка удаляет только отмеченных DEV-врагов без наград/взрывов смерти. Обычные враги остаются, естественный spawn может продолжаться. Предел пула — 144; при заполнении допускается замена уже мёртвых записей, но не удаление живых обычных врагов.

## Ускорение и показатели

Выполняется та же цепочка update с небольшими шагами игрового времени: движение, combat, расход Fuel/Ammo, Power, производство, gathering и события. Номер дня не подменяется отдельно от мира. Переходы времени выполняются постепенно, их можно остановить. Назад день/Chapter не откатываются: для раннего сценария нужна свежая тестовая копия.

×10/×50 — запрошенная скорость, ограниченная производительностью. MAX использует до 240 шагов за кадр и бюджет примерно 12 мс, проверяемый между вызовами update. Один медленный update нельзя прервать посередине, поэтому это не жёсткий предел времени кадра. Пауза, скрытая вкладка и смерть останавливают продвижение. Audio и браузерные интервалы автосохранения остаются на реальном времени. Farm/Animals остаются на прежней паузе.

В консоли и компактном HUD доступны FPS, активные/все enemies, off-zone simulated entities, активные питаемые turrets, длительность simulation update и достигнутая скорость. Off-zone счётчик здесь включает врагов и активные турели вне текущей зоны Player; это не число всех объектов мира.

## Сохранения и архитектура

Save Format остаётся 20. Добавлено необязательное поле devQA0401: DEV/TEST label, исходный слот, command revision/receipts, ID тестовых врагов и overrides существующих событий. Обычные сохранения не получают это поле. Проверяются формат, допустимые IDs и atomic restore; повреждённые данные не применяются частично.

Команды проходят через существующий EquipmentCommands contract с actor/request/revision/idempotency. Повторный запрос после Save/Load не выдаёт ресурс повторно. Настоящие type IDs и instance IDs не заменяются DEV-копиями. Construction → Inventory → Placement, Pick Up, Base Control, Research, Chapter 1, Intro, Archive и Audio сохраняются.

Для отката используйте исходную 0.40.0 и исходный обычный слот, а не тестовый save новой версии. Старые runtime не обязаны понимать отметку DEV/TEST новой сборки.

## Исправленные сопутствующие случаи

1. Дробная погрешность при завершении задания времени могла оставить часы непосредственно перед границей Day X. Завершение теперь проходит через WorldClock.advance с минимальной поправкой, сохраняя событие перехода.
2. Заполненный пул мёртвых зомби больше не мешает повторному ручному Spawn при свободной живой ёмкости.
3. Тестовый переход по старым Chapter objectives с семантикой «после активации» учитывает повторный authoritative refresh; progression не застревает на legacy objective.
4. Repair не восстанавливает стену поверх занятого прохода; повреждённое оборудование восстанавливается только при допустимой геометрии. Упавшие объекты пропускаются.
